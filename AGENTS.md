# AGENTS.md

Guidance for working on agentic-sdk itself. Read this before changing anything
in this repo.

## What this is

agentic-sdk is a runtime-agnostic skill system for software development across
C, Zig, Clojure, and Elixir. This repo is the source. The authoritative design
is [docs/design.md](docs/design.md); read it first when a change touches
architecture, the install model, or the spine.

## Layout

- `skills/<name>/SKILL.md`: the atomic skill catalog (flat). `skills/shared/`
  holds the cross-cutting doctrine references, not a skill.
- `agents/<name>.md`: the 8-agent fleet.
- `src/spine/` + `mino.edn`: the deterministic spine (mino). `test/spine/`
  its tests.
- `hooks/`: hook templates (master form) plus the shared mino policy.
- `templates/`: the project `CLAUDE.md` and `gitignore` skeletons.
- `docs/design.md`: the spec.
- `.opencode/agent/`: derived, generated by `agentic agents sync`; never hand-edit.

This repo keeps its source at the root (`skills/`, `agents/`, `mino.edn`,
`src/`). The `~/.agentic-sdk/<project>/` home applies to installed projects, not here.

## Non-negotiables

- **Prose standard.** No em-dashes, no ASCII arrows in prose, no process IDs,
  terse humanized prose. `agentic lint` enforces it; run it before every commit.
- **No leaks.** Never name predecessor or private projects; the maintainer
  holds the forbidden-token list and it is never written into the public repo,
  not even as a ban list. No domain framing borrowed from another system.
  Generalize any product-specific example to the bounded stack plus Functional
  Core / Imperative Shell.
- **Commits.** jj-first. One line, category-first imperative subject
  (`Skills: ...`, `Docs: ...`, `Fix: ...`, `Build: ...`, `Refactor: ...`,
  `Tests: ...`). No body, no AI attribution, no version numbers. Never advance
  the `main` bookmark or push without the maintainer's say-so.

## Before you commit

- `mino task test`: the spine suite is green.
- `agentic lint $(find docs skills templates hooks -name '*.md')`: zero findings.
- `agentic agents check .`: the derived OpenCode agents match the masters.
- Leak scan: `rg -ni '<forbidden tokens>' skills/ agents/ docs/ templates/ hooks/ src/`

## Changing a skill or agent

Every `SKILL.md` and agent file carries: frontmatter, a one-line role, a
Procedure, a `## Boundaries` section (owns X, sibling Y owns Z), and a one-line
return contract.

- Frontmatter for skills: `name`, `description`, and exactly one visibility flag
  (`disable-model-invocation: true` for the 7 orchestrators and 4 meta-skills;
  `user-invocable: false` for every recipe, primitive, and dimension).
- Frontmatter for agents: `name`, `description`, `tools`, `model`.
- Prefix discipline (design.md section 13.1): `check-` is review dimensions
  only; deterministic gates are `verify-lanes`; planning concerns are `assess-`;
  `write-<surface>` for authoring recipes. One prefix per layer.
- Return contracts are canonical (design.md and
  `skills/shared/references/orchestration.md`): `LANDED`, `ROUND`, `VERDICT`,
  `NO FINDINGS`, `SLICE`, `captured:`, and so on. Do not invent new contracts.

When you change an agent master, run `agentic agents sync .` so the derived
OpenCode form stays in sync, then `agentic agents check .`.

## Adding a skill

Prefer the meta-skills (`bootstrap-project`, `add-language`, `add-dimension`,
`add-tech`) for project-local extension. A new core skill belongs only when it
is genuinely atomic and owns a single concern nothing else owns. Add it under
`skills/<name>/`, follow the shape above, and update the inventory in
design.md section 13.
